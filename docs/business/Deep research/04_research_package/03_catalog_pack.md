## How to Read the Catalog Layer

### Entity atlas

Use when asking:

- what counts as an object in the research universe;
- which objects are universal vs regional vs software-strong;
- which new objects emerged after enterprise and Middle East passes.

### Property catalog

Use when asking:

- what fields, attributes, and links a schedule object may need;
- where task fields stop and governance or PMIS fields begin;
- how schedule data extends into enterprise controls.

### Coding and hierarchy catalog

Use when asking:

- how schedule universes are segmented and rolled up;
- where WBS is enough and where it is not;
- how document, authority, permit, handover, and portfolio layers introduce their own codings.

### Cross-project process map

Use when asking:

- how processes outside pure construction execution appear in schedule systems;
- where approvals, payments, readiness, KPI cycles, or authority workflows enter the model.

### Emergent findings register

Use when asking:

- what the open-search process discovered that was not guaranteed by the initial checklist;
- which non-obvious findings should remain visible during target-model drafting.

## Highest-Signal Catalog Findings

- The object model now materially extends beyond tasks and milestones.
- PMIS, project master schedule, handover, qualification, permit workflow, and performance objects are now evidenced.
- Properties and codes increasingly reflect enterprise and authority systems, not only planning files.
- Cross-project process representation is a structural part of the schedule universe, not an optional annotation layer.

## Recommended Use in Stage 21

Use the catalog pack to shortlist:

- candidate business entities;
- required fields and traceability links;
- hierarchy and coding structures;
- process objects that must remain first-class in the target model.
