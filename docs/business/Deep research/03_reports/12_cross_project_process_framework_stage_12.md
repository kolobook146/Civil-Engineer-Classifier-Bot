# Stage 12: Cross-Project Process Framework

## Purpose

This report formalizes how non-pure-construction processes live inside schedules, using regional evidence and institute artefact models.

## 1. Main Conclusion

Researcher inference:

- Cross-project processes are not peripheral to schedule practice.
- In mature schools and institute systems, they are native schedule content represented as tasks, gates, plans, logs, checklists, package references, contractual events, and digital checkpoints.

## 2. Major Process Families

| Process family | Typical schedule representation | Strongest current clusters |
| --- | --- | --- |
| Initiation and business case | document, gate, phase | PM², EIB, EU public-investment |
| Authorization and chartering | charter, milestone, gate | PM², public-client governance |
| Planning package build-up | work plan, basis, POS/PPR, organization design | CIS, PM², China |
| Procurement and contract formation | package, phase, contractual event | EU, FIDIC, China, ADB |
| Delivery monitoring and reporting | status report, progress report, meeting, review cycle | USA, PM², FIDIC |
| Issue / decision / change control | log, change request, approval stream | PM², FIDIC, owner-side U.S. practice |
| Execution and production control | task hierarchy, look-ahead, short interval | CIS, USA, China |
| Quality, safety, supervision | workstream, gate, control stream, digital record | USA, China |
| Commissioning, handover, closeout | phase, milestone, checklist, contractual event | USA, FIDIC, China |
| Digital supervision and archives | archive, checkpoint, project code, warning object | China |

## 3. Region-Specific Emphasis

### CIS

- strongest on planning package and production execution processes;
- weaker in the first open-source pass on formalized project-initiation artefacts.

### EU

- strongest on initiation, appraisal, procurement, and project-cycle processes;
- less explicit on one common detailed-construction process grammar.

### USA

- strongest on reporting, review, update, and schedule-quality control processes;
- good linkage between execution and governance.

### China

- strongest on coexistence of delivery-governance, construction organization, and digital supervision;
- especially important for process representation beyond tasks.

## 4. Institute-Specific Emphasis

### PMI / AACE

- strongest on decomposition, schedule model, basis, and statusing discipline.

### PM²

- strongest open source for initiation, chartering, work-planning, reporting, logs, and checklists.

### FIDIC

- strongest on contract-lifecycle tasks:
  - project initiation
  - pre-construction
  - execution
  - quality assurance
  - communications
  - financial control
  - claims and disputes
  - closeout

### EIB / EPEC

- strongest on public-investment and PPP process sequencing before and around construction.

## 5. What Changed Relative to the Previous Base

Before this pass, the cross-project-process map already included feasibility, approvals, procurement, and closeout.

After this pass:

- initiation artefacts became first-class processes;
- reporting, logs, and checklists became structured process carriers;
- digital supervision and archive management emerged as a process family, not just a data side effect.

## 6. Main Modeling Implication

The future model should allow a process to be represented as:

- task;
- milestone;
- gate;
- document package;
- reporting object;
- log stream;
- digital checkpoint.

If the model insists that every process must be a task row, it will lose important governance information.
