# Deep Research: Construction and Project Scheduling

This folder contains the research corpus for broad, non-filtered investigation of scheduling in investment construction projects.

## Core Rules

- Do not narrow findings to the future pilot model during the research phase.
- Separate universal principles from regional or jurisdiction-specific practices.
- Separate schedule type from application domain.
- Investigate production schedule and project delivery schedule as distinct but overlapping models.
- Keep an open search posture: capture unexpected entities, rules, fields, codings, and schedule views.
- Use a strict source hierarchy:
  - Level A: primary and practice-significant sources.
  - Level B: strong secondary sources.
  - Level C: auxiliary sources.

## Current Structure

- `00_research_charter.md`: research contour, scope, boundaries, evidence rules.
- `01_templates/`: working templates for comparison matrices and registries.
- `02_registries/`: active registries and seed atlases.
- `02_registries/comparative_matrix_by_extension_system.md`: Stage 23 comparison of heavy schedule-adjacent subsystems.
- `03_reports/`: narrative synthesis documents by stage.
- `04_research_package/`: assembled Stage 20 working package for reading and later model drafting.
- `05_target_model_draft/`: Stage 21 target-model draft derived from the comparative synthesis and research package.

## Working Conventions

- Research discussion with the user is in Russian.
- Research artifacts in this folder are in English.
- Existing files in `docs/` outside this folder are intentionally not used in this phase.
- Synthesis statements that combine multiple sources are marked as researcher inference.
- In the software layer, products with strong openly inspectable official documentation are prioritized over products with weaker public technical detail.
- In the extension-systems layer, runtime object and workflow visibility takes priority over broad marketing claims.
