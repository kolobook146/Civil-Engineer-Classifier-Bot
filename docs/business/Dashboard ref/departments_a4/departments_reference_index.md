# `departments_a4` Reference Index

Purpose: keep the `departments_a4` responsibility-dashboard layout tied to mature construction / capital-project controls practice without turning the pilot into a full enterprise PMO suite.

## Reference Principles

- Owner-side reporting connects responsibility structures with schedule, cost, risk, and action ownership.
- Department or workstream pages should be exception-led: show where intervention is needed, not only aggregate totals.
- `PV / EV / AC` is useful by responsibility bucket when clearly treated as a project-controls proxy rather than a financial ledger.
- Heatmaps are appropriate for fast visual scanning across responsibility buckets and delivery phases.

## Source Notes

| Source | Type | What to Borrow | Dashboard Implication |
| --- | --- | --- | --- |
| GSA Kahua Monthly Status Report | Official owner PMIS guidance | Monthly status reporting, milestones, risks, project directory, and current-state discipline | Keep responsibility dashboard connected to schedule status and exception escalation |
| UK GovS 002 Project Delivery Standard | Official project-delivery standard | Governance, roles, responsibilities, factual status, risks, issues, decisions | Treat `Responsible` as accountability structure, not a decorative label |
| UK Teal Book: Controlling | Official project-delivery guidance | Control cycle, deviations, corrective action, progress monitoring | Include delay signal and attention ranking |
| AACE Earned Value guide | Project-controls professional guidance | Earned value vocabulary and responsibility-linked control logic | Use `PV / EV / AC`, `SPI`, and `CPI` carefully by responsibility bucket |
| DOE Project Dashboard example | Official owner dashboard example | Portfolio performance dashboards with cost and schedule health indicators | Keep top KPI band and RAG summary compact |
| Ashghal APMS training page | Owner PMIS / programme reporting context | PMIS-enabled project and programme controls environment | Treat dashboard as a controlled reporting surface, not an ad hoc sheet |
| Ashghal QA/QC monitoring paper | Construction management / monitoring source | Structured dashboard monitoring for quality and contractor oversight | Reinforces operational watch and exception ranking |
| Planera / SmartPM / Autodesk / Sphere examples | Vendor visual references | Modern construction dashboard visuals: large cards, bars, heatmaps, subcontractor performance views | Use visual patterns only as support, not as methodology |

## Adopted For Pilot

- `Department Performance Scoreboard`
- `Responsible x Stage Progress Heatmap`
- `Department EVA / Cost Exposure`
- `Department Delay Signal`
- `Departments Requiring Attention`

## Deliberately Deferred

- Person-level performance scoring.
- Full RACI / workflow ownership matrix.
- Contractual claims, payment, and commercial entitlement attribution by department.
- Formal corrective-action workflow status inside the dashboard.
